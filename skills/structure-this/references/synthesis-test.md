# The synthesis test

## The rule

Every node in the pyramid must say something. A node that announces a category
has said nothing — it has only told the reader that a category exists, and
left them to do the thinking themselves.

- For a group of **actions**: the synthesis is the *result their combination
  produces* — not a count or a label for the actions.
- For a group of **situations**: the synthesis is their *common implication* —
  what the situations, taken together, mean.
- This is the sharpest test in the method, and the one place where real
  thinking has to happen. Everything else in the pyramid — grouping, ordering,
  induction versus deduction — is organisation of thought that already exists.
  The synthesis test is where new thought gets produced.

## How to test it

The cover test:

1. Cover every child under a given node.
2. Read the parent line alone, with nothing else.
3. Ask: would a reader who saw only this line know something they did not know
   before?
4. If the line only tells them a category exists ("there are some problems,"
   "here are some considerations") without saying what the problems add up to,
   it fails. Rewrite it as a sentence that asserts a conclusion.

## Failure modes

Reject any parent node that reads as one of these — they name a category
instead of asserting a conclusion:

- "There are three problems"
- "Five changes are needed"
- "Key considerations"
- "Next steps"
- "Challenges"
- "Findings"
- Any heading that is a noun phrase naming a topic rather than a sentence
  asserting a conclusion (a rule of thumb: if it could be a slide title with no
  verb doing real work, it has failed).

One worked repair:

```
Rejected:  Three issues affect the rollout.
Repaired:  The rollout will slip a quarter unless staffing is fixed first.
```

The rejected line counts issues. The repaired line tells the reader what those
issues mean for the thing they actually care about — the timeline.
